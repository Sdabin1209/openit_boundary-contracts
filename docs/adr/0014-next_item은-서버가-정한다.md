# 0014 next_item은 추론 서버가 정한다

- 상태: 채택(2026-11-02, 3.1.3)
- 맥락: `ActionExtraction.next_item`(다음 문항)을 모델이 내고 서버가 규칙으로 대조했다. 학습 안 된 모델(데모 중립 LoRA)은 순서표에 없는 문항을 내 턴이 저장되지 않았고(UNKNOWN_ITEM), 학습된 모델도 문항 순서표가 바뀌면 같은 식으로 틀린다. 다음 문항 선택은 문진의 항법(순서·건너뛰기)이지 발화 이해가 아니다(U74).
- 결정: 추론 서버가 `action`·`targets`·`values`와 문항 순서표(flow)로 `next_item`을 정해 채운다(`fill_next_item`). 규칙 데이터에 `next_item.derived_by: "server"`를 둔다. 모델 값은 덮어쓴다. `check_action_extraction`은 채운 값을 확인만 한다.
- 왜: 항법 정보(순서표)는 이미 매 호출에 서버로 간다(I9 ExtractRequest.flow). 그 정보를 가진 쪽이 정하는 것이 규칙 4(컴포넌트는 자기 입출력만 안다)에 맞고, 모델은 현재 문항의 값만 책임진다.
- 검토한 대안: (a) 모델 프롬프트에 문항 순서를 넣는다 — 항법을 모델에 떠넘기는 것을 굳힌다, 버림. (b) survey-service가 정한다 — 서비스는 서버가 보증한 출력을 다시 검사하지 않는다(R7)는 원칙과 충돌하고 두 곳이 같은 규칙을 갖게 된다, 버림.
- 결과: 와이어 형식 변경 없음(PATCH). 모델 출력의 `next_item`은 더 이상 품질 지표가 아니다. 학습 데이터의 next_item 정답은 그대로 두되 서빙에서는 쓰지 않는다.
- 되돌리는 조건: 문항 순서가 발화에 따라 달라지는 요구(순서표로 표현 못 하는 항법)가 생기면 재검토한다.
