# 0010. 직원 호출 전달 실패에 재알림 API와 실패 기록 API를 더한다 (CR-H001)

- 상태: 수용(2.1.0, 사용자 위임 아래 헤드 결정, 헤드 CR-H001)
- 관련: D88, D89 / `PUBLIC_API.md` G절 / 헤드 `docs/change-requests/CR-H001-staff-call-redelivery.md`

## 맥락

위험 정지나 직원 호출 때 전달 경로가 하나도 살아 있지 않으면 응답에 `staff_alert = DELIVERY_FAILED`가 실린다. 키오스크는 "직원을 직접 부르는 화면"을 보여 주는 데서 멈추고, 서버에 다시 부르라고 요청할 방법도, "안 닿았다"를 기록할 방법도 없었다. 환자가 위험 신호로 멈춘 상태에서 직원이 오지 않으면 키오스크와 서버 모두 알 수 없다.

## 결정

- `POST /v1/sessions/{id}/staff-call/retry`(본문 `{turn_id}`): 그 세션의 `OPEN` 알림을 새로 만들지 않고 **같은 `alert_id`로** SSE·푸시에 다시 보낸다. 응답은 `StaffCallRetryResult`.
- `POST /v1/sessions/{id}/staff-call/report`(본문 `{outcome, turn_id}`): 키오스크의 "직접 알리셨나요?" 응답을 알림에 남긴다. 응답은 갱신된 `StaffAlert`.
- `StaffAlert`에 optional 필드 `delivery_attempts`, `last_delivery_status`, `manual_notice_outcome`, `manual_notice_reported_at`.
- 키오스크 기기 토큰만(세션을 만든 기기). 같은 `turn_id`는 멱등. 간격·횟수 하한은 429(`Retry-After`, `details.reason` = `TOO_SOON`|`RETRY_LIMIT`).
- **간격과 횟수의 값은 계약이 아니라 서비스 설정이다.** 계약의 권고 기본값은 30초·세션당 10회이며 **측정하지 않았다.** 임상·현장 흐름 자료가 없다. 값은 survey-service가 자기 ADR에 근거와 함께 적는다(D89).

## 왜

- 환자 안전 경로가 키오스크 화면 상태에만 의존하면 안 된다. 서버가 전달 실패를 알아야 직원 콘솔이 나중에 열려도 "전달 실패 알림"을 구분해 보여 줄 수 있다.
- 같은 `alert_id`로 다시 보내는 이유: 새 이벤트 이름(`alert_retry`)은 모르는 콘솔이 무시하므로 목적을 못 이룬다. 같은 `alert` 이벤트와 같은 ID면 기존 콘솔의 중복 처리(ID 기준)에 맡길 수 있다(기존 콘솔의 처리는 이 리포에서 확인하지 못했다. 합치지 않으면 화면에 중복이 보이는 정도이고 알림은 놓치지 않는다).
- 표준 관행: 멱등 키(`turn_id`, CONVENTIONS 4절)와 429 + `Retry-After`(HTTP 표준, RFC 6585·9110)를 쓴다. 이 리포의 기존 규약(PUBLIC_API 오류 표)을 그대로 따랐다.
- 값을 계약에 박지 않는 이유: 측정 없는 숫자를 모든 영역이 따르게 하면 현장에서 바꿀 때마다 계약 버전이 올라간다. 설정이면 서비스가 바꾼다.

## 검토한 대안과 버리는 이유

| 대안 | 버리는 이유 |
|---|---|
| 지금처럼 키오스크 화면만 | 서버가 "안 닿았다"를 모른다. 비용 0이지만 문제를 그대로 둔다 |
| 위험 감지기 경로(`risk-signals`)로 키오스크가 새 신호 | `risk-source` 역할 전용이고 알림이 중복되며 권한 범위가 넓어진다 |
| 키오스크에 `GET /v1/staff/alerts` 읽기 | 직원 전용 목록이라 역할 분리를 흐린다. 직원 확인(ack) 개념도 없다. 후속 후보 |
| 서버 내부 재시도 큐 | 보완책이지 대체가 아니다. 구독자가 없으면 닿지 않고 현장이 다시 부를 방법이 없다. 별도 후속 |
| 같은 `turn_id` 발화 재전송으로 재전달 | 환자 발화 없이 못 하고 위험 선별은 세션·턴 기준 멱등이라 새 알림이 안 생긴다 |
| 간격·상한을 스키마 상수로 고정 | 측정 없는 값을 계약에 박게 된다 |

## 결과

- 얻는 것: 환자 안전 경로의 빈칸 해소, 직원 콘솔의 전달 실패 가시성.
- 감수하는 것: survey-service(가장 큰 변경), kiosk-frontend의 구현이 필요하다. 새 키오스크 + 옛 서버는 경로가 404이므로 기능 감지로 현재 동작으로 물러난다. `NOT_NOTIFIED` 뒤 환자 안내는 임상 확인이 남은 미정이다.

## 되돌리는 조건

현장에서 직원 확인(ack) 개념이 도입되면 재알림 의미를 다시 본다(새 ADR이 `Supersedes`).
