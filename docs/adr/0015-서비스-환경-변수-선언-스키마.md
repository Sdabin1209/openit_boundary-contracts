# 0015 서비스 환경 변수는 계약의 선언 스키마에만 있다

- 상태: 채택(2026-11-03, 3.2.0)
- 맥락: deploy 가 각 서비스 컨테이너에 주는 설정 변수 이름, 비밀 파일 이름, 잡 이름, 지표 이름이 계약 밖에 있었다(U73, 구조 규칙 6 위반). 영역은 이웃 문서를 베껴 이름을 썼고, 한쪽이 바꾸면 기동 전에 걸리지 않고 실행 중에 깨졌다. 서비스 4개(model-serving, release-gate, model-registry, dataset-store)와 프런트에는 선언이 아예 없었고, 있는 선언도 설명이 비어 있었다.
- 결정: 서비스마다 환경 변수 선언 스키마를 계약에 둔다(`ModelServingEnv`, `GateEnv`, `ModelRegistryEnv`, `DatasetStoreEnv`, `KioskFrontendEnv`, `QuestionAuthoringEnv`, 기존 `SurveyServiceEnv`·`OpsFeedbackServerEnv` 개정). 변수마다 뜻·값 형식·기본값·비밀 여부를 적는다. deploy 는 선언된 이름만 주고, 서비스는 기동 때 자기 environ 을 자기 선언으로 검증한다. 모양은 `SurveyServiceEnv` 의 것(접두사가 붙은 이름은 enum 으로 닫고, 접두사 없는 변수는 보지 않는다)으로 통일한다.
- 왜: 영역 사이 값은 전부 계약 스키마에 있어야 한다(규칙 6, 사용자 결정 2026-11-02 "스키마 밖은 어떤 경우에도 없다"). 선언이 있으면 오타·폐기 변수·누락이 기동 때 걸린다. 뜻은 각 영역의 설정 로더와 runbook 에서 옮겼고 모르는 것은 "미정"으로 표시했다(지어내지 않는다, 사용자 지적 2026-11-02).
- 검토한 대안: (a) additionalProperties:false 로 environ 전체를 닫기 — PATH·HOME 같은 이미지 변수 때문에 불가. (b) 각 영역 리포 안에 선언을 두기 — 영역 사이 이름이므로 헤드 소유 계약이어야 한다(규칙 6). (c) 이름만 열거하고 뜻은 생략 — 뜻 없는 스키마는 본질을 덮는다(사용자 지적), 버림.
- 결과: 영역은 3.2.0 열차에서 기동 검증을 넣는다. 선언에 없는 변수를 쓰면 기동 실패. 비밀 파일 이름은 각 `*_FILE` 변수의 값으로 선언된다. 잡 이름은 `JobsDeclaration`, 지표 이름은 `METRICS.md` 가 맡는다.
- 되돌리는 조건: 설정 체계를 환경 변수에서 설정 파일 하나로 바꾸면 선언도 그 파일 스키마로 옮긴다.
